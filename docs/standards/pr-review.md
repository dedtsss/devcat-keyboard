# PR Review Standard

## Rule

Every PR should be small enough to review and must state what changed, how it was checked and what risk remains.

## Details

- Prefer one clear purpose per PR.
- Include user-visible behavior, documentation updates and validation commands in the PR body when relevant.
- Do not hide unrelated formatting, refactors or generated changes inside a functional PR.
- For checklist items, use the repository PR template first and add task-specific notes only where useful.
