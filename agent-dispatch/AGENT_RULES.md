# Agent Dispatch Rules

Эти правила обязательны для Codex, Manus, ChatGPT и других агентов, которые выполняют задачи проекта.

## Главное правило

Задача не считается выполненной, пока результат не доступен в GitHub.

Ответ в чате без ссылки на репозиторий, ветку, commit, PR или отчёт не является завершением задачи.

## Обязательный финальный протокол

Перед завершением любой задачи агент обязан:

1. Зафиксировать результат в GitHub.
2. Указать точный репозиторий в формате `owner/repo`.
3. Указать ветку или commit SHA.
4. Создать или обновить итоговый отчёт.
5. Указать путь к отчёту.
6. Написать, какие тесты или проверки выполнены.
7. Прямо указать блокеры, если что-то не получилось.

## Где писать статусы

Для каждой задачи используются три зоны:

- `tasks/` — исходная постановка задачи.
- `status/` — текущий статус выполнения.
- `reports/` — итоговый отчёт.

## Статусы

Разрешённые статусы:

- `planned`
- `in_progress`
- `blocked`
- `review_ready`
- `done`
- `failed`

## Формат блокера

Если агент не может завершить задачу, он обязан записать:

```text
Status: blocked
Reason: <краткая причина>
Required action: <что нужно сделать дальше>
Last successful step: <последний реально выполненный шаг>
Artifacts: <что уже создано, если создано>
```

## Запрещено

Запрещено:

- писать `готово`, если результата нет в GitHub;
- ссылаться только на локальное окружение;
- оставлять работу без отчёта;
- менять не тот репозиторий без явного указания;
- хранить секреты, API-ключи, токены и пароли в отчётах или коде;
- подменять фактические проверки фразами вроде `должно работать`.

## Минимальный отчёт

Каждый `WORK_REPORT.md` должен содержать:

1. Название задачи.
2. Статус.
3. Репозиторий.
4. Ветка/commit.
5. Что сделано.
6. Как запустить.
7. Какие тесты пройдены.
8. Какие файлы ключевые.
9. Что не сделано.
10. Следующие шаги.

## Проверка другим агентом

Проверяющий агент обязан читать GitHub, а не полагаться на пересказ из чата.
Если отчёта, PR, commit или репозитория нет — задача считается неподтверждённой.
